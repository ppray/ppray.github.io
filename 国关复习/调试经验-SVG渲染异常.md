# 调试经验：SVG 渲染异常（黑块 / 缺线 / 文字乱位）

> 来源：2026-08-09 同步《货币与金融的国际政治经济学》图表集时的真实教训。
> 用户报告"部分图表缺线、有黑块""图16 文字不在图内"，我多轮验证"无法复现"，
> 最终用户亲自定位到根因。以下记录根因、我为何漏判、以及可复用的排错规则。

---

## 一、根因（两个独立 bug，叠加出现）

### Bug A：CSS 变量未定义 → 黑块 + 缺线
复习笔记的 SVG 大量用 `var(--primary)`、`var(--text-main)`、`var(--text-muted)`、
`var(--border)` 等变量，但图表集的 `:root` 没定义它们。

- `stroke="var(--text-muted)"` → 变量不存在 → stroke 失效默认 none → **连线/箭头消失**
- `fill="var(--primary)"` → 变量不存在 → fill 失效默认黑 → **圆点/方块变黑块**

**修法**：在图表集 `:root` 补上这些变量（取浅色值，因 SVG 在深色模式也强制白底）。

### Bug B：SVG `<text>` 内嵌套 HTML `<b>` → 解析崩溃 → 文字乱位
源 SVG 写了 `<text>伪造维度：<b>价格</b></text>`。
SVG 规范里 `<text>` 是叶子文本节点，**不允许嵌套 HTML `<b>`**。

浏览器首次解析 HTML 时：遇到 `<rect>` 能正常画（在第一个 `<b>` 之前），
遇到 `<b>` 就把后续内容**退出 SVG 解析、按 HTML 流式渲染**——于是蓝框紫框画不出来，
三组文字全被甩到 SVG 下方堆成一坨段落。

**修法**：把 `<b>…</b>` 全部换成 `<tspan font-weight="700">…</tspan>`。

---

## 二、我为什么没找到 Bug B 的根因（复盘）

**核心失误：我所有验证都在"DOM 层"跑，而 Bug B 是"HTML 解析层"的问题。两者不在一个层面。**

| 我用的方法 | 为什么测不到 Bug B |
|---|---|
| `getBBox()` 测文字溢出 | 用 `innerHTML` 注入 SVG。脚本注入会触发**重新序列化再解析**，浏览器把损坏结构规整成合法 DOM。我测的是"被修复过的 DOM"。 |
| Chrome `--dump-dom` / 截图 | headless 拿到的是**解析后**的 DOM，Chrome 容错强会自动恢复。 |
| 视觉模型看截图 | 截图来自上述"修正版"渲染，自然正常。 |
| 计算字号×字数 vs 框宽 | 整个分析前提（结构正确）就是错的，后面算再准也没用。 |

**最致命**：4 次都"正常"时，我没怀疑验证方法共享盲区，反而得出"无法复现，可能你环境问题"，
还让用户补信息。把工具盲区误当成了问题不存在。

---

## 三、可复用的排错规则（记下来，下次照做）

### 规则 1：源文件原文是最直接证据，先于任何运行时测量
遇到 SVG/HTML 渲染异常，**第一步直接读源文件原始文本**，grep 非法结构。
不要一上来就跑 getBBox / 截图 / 视觉模型——那些都是"解析后"的产物，会掩盖解析层 bug。

### 规则 2：结构合法性优先于渲染测量
先验"标签嵌套合不合法"，再测"渲染对不对"。
- SVG `<text>`/`<tspan>`/`<textPath>` 是 SVG 命名空间，**禁嵌** `<b><strong><i><span><div>` 等 HTML 标签。
- HTML 标签想进 SVG，必须用对应 SVG 元素：加粗→`<tspan font-weight>`，分段→多个 `<tspan>`/`<text>`。

### 规则 3：解析层 ≠ DOM 层
- **解析层 bug** 只在首次 HTML 解析时触发（非法标签嵌套、未闭合标签、命名空间混淆）。
- 一旦内容进了 DOM（innerHTML / fetch+注入 / Chrome dump），结构已被规整，bug"消失"。
- 排查解析层问题，**必须用静态文本分析（读源文件、正则 grep），不能用运行时 DOM 检查**。

### 规则 4："多次验证一致" ≠ "问题不存在"
当 N 种方法都说正常、但用户坚持有问题时：
- ❌ 错误反应：怀疑用户、怀疑环境、让用户补信息。
- ✅ 正确反应：怀疑**所有方法共享同一个盲区**。问自己"我的工具是不是都在同一层面失效？"

### 规则 5：CSS 变量缺失是 SVG 黑块/缺线的高频根因
SVG 用 `var(--xxx)` 而 `:root` 未定义该变量时：
- `stroke=var(...)` → 线消失（缺线）
- `fill=var(...)` → 变黑（黑块）
排查 SVG 颜色异常，**先 diff 两个文件的 CSS 变量定义集**：
`grep -oE 'var\(--[a-z-]+\)' f.html | sort -u` 比对"用了哪些" vs "定义了哪些"。

---

## 四、一句话总结
> **SVG 渲染坏了，先静态读源文件查"结构合不合法 + 变量有没有定义"，再谈渲染测量。
> 运行时 DOM 检查会自动修复解析层 bug，是这类问题的检测盲区。**
